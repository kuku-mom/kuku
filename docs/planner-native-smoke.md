# Native Planner smoke test

Run `node scripts/planner/native_smoke.mjs` on macOS with the repository's Node and Rust dependencies available. The runner builds an explicit `native-smoke` feature, starts its own Vite preview server on port 5179, and launches a separate **KukuPlannerSmoke** process. If that port is already occupied, it fails instead of attaching to or stopping another process. `--skip-build` reuses the dedicated binary cached at `target/native-smoke/KukuPlannerSmoke`; it never reuses an ordinary app from `target/debug` without first building the test feature. The production frontend is built into the temporary run directory to prevent concurrent source edits from interrupting tests through HMR.

Add `--controls-only` for source/filter selection, search/sort, date navigation, and composer Escape checks. Add `--probe-only` to check isolated application launch and actual rendering before running interactions. The default run also covers task dragging, native persistence, availability suggestions, and the narrow layout. All modes clean up only the test runner's own processes. `KUKU_SMOKE_FRONTEND=/absolute/path/to/previous/frontend` can reuse a previously frozen build while diagnosing the harness; omit it for final acceptance against current sources.

The runner wraps its dedicated binary in a temporary `.app` and opens it through macOS LaunchServices using `open -n --env`. It does not use AppleScript, Accessibility, or native event injection. macOS can pause animation frames in a fully occluded WKWebView; a bare executable launch previously produced zero frames. If the new test document is hidden, the runner confirms the exact isolated process is still running and reopens that same `.app` once with `open` (without `-n`). The application's existing Tauri `RunEvent::Reopen` handler shows and focuses its own window. It waits at most ten seconds for visibility, then still requires the original visible-document/two-frame barrier; a locked or persistently hidden session remains a failure. Any reopen measurements are saved in `native-reopen.json`. The test also requires settled composer/menu opacity before capturing their screenshot. Measurements are saved in `native-paint.json` and `native-controls-paint.json`. Cleanup resolves the temporary executable's canonical path before checking its exact PID; existing Kuku processes are never terminated.

The test runs the production Planner UI inside a real WKWebView. Local task edits go through the production Tauri vault commands and write to a temporary vault. Google and Apple sources stay disabled; the runner only captures their read-only connection status in `provider-status.json`. It does not open OAuth, request EventKit permissions, or write to a live account. The browser-only synthetic fixture remains available separately for external-provider scenarios.

Assertions cover opening the custom task-source and filter menus and choosing their local options, lifting an unplanned task, shrinking its card while hovering over the calendar, restoring its original size outside the grid, and cancelling with Escape without note changes. The same run then checks clicking a blank slot and opening its custom calendar menu: the first Escape closes only the menu and keeps the entered draft; the second closes the composer without writing a note. It also checks selecting a 60-minute range with pointer actions, saving an Inbox task and its schedule metadata, moving its time block with pointer actions, and restoring the saved block after reloading. Each run prints an evidence directory containing its vault, logs, screenshots and result JSON, including the measured card sizes before, during and after calendar hover. Failure runs save the DOM and screenshot when the native driver is available.

Search checks filter real note tasks, clear with Escape, order by title, and restore query/sort after reload. The date shortcut accepts a typed future date, keeps its popup within the Planner pane, and exposes the direct-date field and Today button. A separate native window resize enables both app sidebars to produce a real 450px Planner pane at a 760px content height, then verifies the expanded task drawer and complete date popup. Availability checks identify a 30-minute overlap with the newly saved local task and apply a suggested free slot without writing the draft before Save. These use production handlers and actual persisted Markdown rather than fixture command responses.

Add `--ai` for the native AI integration path:

```sh
node scripts/planner/native_smoke.mjs --ai
```

This enables the normal AI chat plugin's proxy bridge and checks all 17 Planner descriptors in the native registry, including their access classifications. The optional `planner_smoke_ai_tool` command provides deterministic model-call input to the production mode gate and proxy broker. Ask and Inline mutation calls are rejected before note changes; Ask search/read/availability and Agent task creation, revision-checked title/deadline edits, scheduling, completion, unassignment and deletion pass through the real frontend handlers and native vault commands. Retrying a creation with the same request ID is checked both in the current process and after a full WebView reload. A stale revision must fail without changing the file. The test preserves the seeded note and the UI-created task while deleting only its own AI test task. Results and test-only tool traces are saved in `native-ai.json`.

The deterministic entry point is compiled only with `native-smoke`, rejects non-Planner names, and checks the isolated bundle identifier and explicit smoke environment. It is absent from ordinary Kuku/KukuDev builds and cannot be included in release builds. `--ai` does not contact a live model: it verifies production tool dispatch and permissions. Use a normal build after the smoke build when preparing KukuDev for a user.

Use `--live-model` only when the user has authorized testing their configured KukuDev model. This makes billable network requests using the model already selected in KukuDev:

```sh
node scripts/planner/native_smoke.mjs --live-model
```

For a focused retry after the UI suite has already passed, use `--live-model-only`. It keeps the actual native paint barrier, isolated seeded note, production Planner loading, and live-model assertions while skipping the repeated menu/drag/responsive suite and deterministic tool calls. `Tasks/Inbox.md` starts absent; Ask must leave it absent, and the normal Planner create path must create it on the Agent request. Add `--skip-build` only when the dedicated smoke binary already contains the current backend.

The runner explicitly sets `KUKU_NATIVE_SMOKE_LIVE_MODEL_SOURCE=kuku-dev`. After all UI tests and reloads finish, `planner_smoke_ai_use_configured_model` reads the existing public KukuDev provider/model configuration and its fixed Keychain credential in native code. It returns only provider/model/source. The runner announces that it is waiting for macOS Keychain and grants this setup call 120 seconds for any normal OS authorization prompt; both WebDriver script and request timeouts return to 20 seconds afterward. The credential stays in native memory: it is not copied into the temporary app's settings, passed to WebDriver, or printed. The harness never calls `ai_get_config`. Verbose smoke output is rejected, and the launched test process disables Rust tracing and backtraces for this mode.

The live path sends ordinary Korean requests through `ai_new_session` and `ai_send_message`, without supplying tool names or injecting tool calls. It checks that Ask actually searches Planner without changing either note, then that Agent chooses Planner tools to create exactly one Inbox task and schedule the specified local hour. A follow-up asks Agent to complete that task; the saved Markdown must retain its schedule and leave the deadline and other note content unchanged. The corresponding block must appear, and remain completed, in the real native calendar. `native-live-model.json` records the configured public model, prompts, actual tool events, model text, completion status, and final task metadata. Provider errors include a category and at most 2,000 characters of the native adapter's sanitized message, with additional query-key redaction in the capture. The in-memory model configuration is reset at completion or cleanup.

Live-model runs retain the same isolated temporary vault and disconnected calendar sources. They verify the selected model's actual tool choices and native local persistence; they still do not write to Google Calendar or Apple accounts.

The embedded driver's current W3C `actions` implementation dispatches `MouseEvent` for mouse down/up/move, which does not invoke the Planner's gesture handlers or Kobalte's mouse `PointerDown` trigger. Gesture and custom-menu assertions therefore dispatch `PointerEvent` through WebDriver script execution inside the actual WKWebView. Escape checks similarly dispatch keyboard events to the focused element. They verify the real renderer's interaction logic and native persistence, but do not verify OS-level input injection or trusted input events. Other button and text-field interactions use ordinary WebDriver element commands.

The harness uses the published `tauri-plugin-wdio-webdriver` 1.3.0 embedded driver and standard W3C WebDriver requests. This is the same embedded driver documented by Tauri and WebdriverIO for macOS. It requires no paid driver or extra frontend command-mocking plugin. The driver binds to loopback and only exists in the optional Cargo feature. The test binary refuses to run without explicit smoke environment variables and its own bundle identifier; attempting to build the feature for release is a compile error. Production and ordinary KukuDev builds do not include the driver. App data, settings, WebView storage and Keychain service names are isolated from the user's normal app variants.

This verifies native rendering and local persistence. It does not substitute for real Google OAuth or macOS permission and account-sync acceptance testing.
